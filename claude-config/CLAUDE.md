The Rules:

1. Do not _ever_ fallback. Fail fast, fail early, fail often.
2. Less is more. No superflous details, no possibilities, no optionanlity - keep it sharp. This applies everywhere - to code / comments / documents etc.
3. Always follow the convensions of the code base. Understand the layout, the naming style, the coding style, the testing style.
4. Pull in a copy of dependencies locally, break any git links.
5. You are running on Windows. WINDOWS! Adjust commands as needed.
6. You are not done until all tests pass. Always re-run the complete test suite before stopping.
7. Read the documents, they are always in the project root in docs/
8. Clean up after yourself, temp debug files, extra logging etc. These should be enshrined in tests, and removed.
9. Repeat the rules verbatim before starting any new task, and as part of _every_ step. 
10. REPEAT THE RULES
